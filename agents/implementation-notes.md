# Implementation notes -- the FkRecipes build report

Working notes for the v1 build, 2026-08-31. This file is a deliverable equal to the code: every design deviation with evidence, every piece of ecosystem friction met while dogfooding FkLua's distribution machinery, every cross-language mirror gap, and the gate results. Unresolved issues are recorded here, never papered over. The charter is FkLua's agents/drafts/recipes-library-design.md (decisions resolved 2026-08-31).

## Ecosystem friction, graded

Each entry says what was tried, what happened verbatim, and the grade: CLEAN (worked as documented), AWKWARD (worked but cost something), MISLED (pointed the wrong way), BLOCKED (needed a workaround).

### The Go require resolves: CLEAN, and now rides v0.2.0

`go/go.mod` requires `github.com/Techrocket9/fklua/guest/go v0.1.0` with no replace. `go mod tidy` printed `go: downloading github.com/Techrocket9/fklua/guest/go v0.1.0`, exited 0, and wrote a two-line go.sum. At that moment the scaffold's guest.go imported the module behind `//go:build tinygo.wasm` and tidy kept the require (tidy considers all build tags). The real channel works first try. Caveat recorded by the Go review: once guest.go became a placeholder with no import, `go mod tidy` would DELETE the require and both go.sum lines; the require becomes load-bearing again when the emit layer imports fkdata. Do not run tidy in the placeholder window. The window closed with the emit layer: `go mod tidy -diff` exits 0 with no diff. Moved to `guest/go v0.2.0` for the raise import: `go mod tidy` downloaded it and exited 0, and the example module's own go.mod moved with it. Both go.sum pairs rewritten.

### The cargo git dependency finds fkdata: CLEAN, and now rides the same head as the harness

`rust/Cargo.toml` declares `fkdata = { git = "https://github.com/Techrocket9/fklua" }`, wasm-gated. `cargo fetch` updated the git repository and locked fkdata 0.1.0 plus its fk dependency at commit efcc71e8, exit 0. Cargo found the named package with no root Cargo.toml in that repo (the workspace root is guest/rust/) by scanning; fkdata's own `fk = { path = "../fk" }` resolved inside the fetched checkout. Cargo.lock is committed, matching FkLua's guest/rust convention. ASYMMETRY CLOSED: the lock pinned efcc71e8 while the harness built fklua from whatever `FKLUA_CHECKOUT` happened to be, so the library and the tool it is packaged by could skew silently. `cargo update -p fkdata -p fk` moved both to 83c62cd4, which is the checkout head the harness builds from; the library dependency and the harness now ride the same commit, and a future skew shows up as a lock diff rather than as a mystery. The skew showed up exactly that way one round later: FkLua's pushed head moved to ac0ebcc (two commits, a drafts note and fk_module.map.json in packaging output) while the lock still said 83c62cd4, and the lock was moved again to match. The FkLua-side doc commit for this repository's raise-prefix ask sits one commit ahead of the pushed head until the operator pushes; it changes comments and docs only, so the harness built from the checkout and the library pinned to the pushed head behave identically, and the lock moves once more after that push.

### `fklua init --library` for two languages: CLEAN, with the refusal doing the teaching

Running `fklua init --library fkrecipes --lang go,rust` refuses with:

    fklua init: --library scaffolds ONE language per directory; a two-language library is two sibling trees with a mirror test between them (the fkipc arrangement), so run init --library twice, in sibling directories

Running it twice in `go/` and `rust/` scaffolded exactly the documented four Go files and two Rust files, refused nothing else, and printed the composition-contract closing message both times.

### The scaffold is control-stage flavored: MISLED (mildly), for a data-stage library. RESOLVED upstream

`init --library` has one flavor, and it is a control-stage library: the example surface is `OnTick`/`OnEvent(id, ptr) bool` routing, the guest half calls `fk.Log`, the Go guest imports `guest/go/fk`, the Rust Cargo.toml declares `fk` as the wasm-gated dependency, and the generated contract comments emphasize event routing and multiplayer join safety. A data-stage library needs `fkdata` in both manifests and has no events at all, so both dependency declarations and both guest halves were rewritten by hand. The parts that transfer anyway (route-never-own, the build-gate split, no_std under cfg, the fk/fkgc feature ban, the [patch] one-source note) transfer verbatim. A `--data` flavor, or one sentence in the closing message saying "a data-stage library swaps fk for fkdata", would have removed the detour. RESOLVED: `fklua init --library <name> --lang go --data` exists. Its contract text is better than what this library had in two places, and both were adopted into the package docs: "Never iterate a Go map to decide what to emit: the data stage crosses sorted, and a map walk is a per-client order" states the mechanism where ours stated only the consequence, and the DIAGNOSE WITH Raise clause is the rule this round adopted.

### The scaffold's go.mod placeholder: AWKWARD. RESOLVED upstream

The generated `module fkrecipes` line carries a comment saying to rename it to the publishing path, which is right, but says nothing about the sibling-directory arrangement it itself prescribed one refusal earlier: a module living in the `go/` subdirectory of a repo must carry the `/go` suffix in its module path (`github.com/Techrocket9/fkrecipes/go`) or consumers cannot fetch it. One sentence in the comment would close the gap. RESOLVED upstream.

### fklua mod packages the examples first try: CLEAN, with two advisory notes. BOTH RESOLVED upstream

Packaging both example guests worked with no refusals and no surprises, and --report drove every harness assertion (.ok, .hooks.data exactly [fk_settings, fk_data], .hooks.control empty, the data-updates and final-fixes files correctly absent). Two notes for FkLua rather than defects here. First, the NaN advisory prints 22 NaN-sensitive operations before the success lines, naming THIS LIBRARY's internals ((*Lib).Emit 17 times, PlanData, toV, fromV) in every consumer's packaging output; it is harmless for fkrecipes (the planner refuses every non-finite value before it can reach an op, so the sign and payload loss is unobservable) but a consumer packaging any mod that uses this library sees a wall of text about code they did not write and cannot action. Second, .pruning reports members, events and defines as 0/0 with complete false, which is correct for a data-only mod with no fkapi but reads like a problem at a glance. Also cosmetic: the advisory renders the Go World interface's whole method set inline as a symbol name, three times; the cost of an interface where Rust's trait object has no such symbol.

BOTH RESOLVED upstream, re-measured by re-running the harness packaging on 83c62cd4. The NaN advisory now caps the wall: 25 operations reported, eight named entries, then `  ... and 17 more of the same class`, with the remedy paragraph kept intact ("Most programs never observe this. If yours does, recompile with --nan=exact, which preserves NaN bits at a substantial speed cost."). The pruning block now reads `"pruning": {"members": {"complete": true, "shipped": 0, "total": 0}, "events": {...}, "defines": {...}}` with `"api": {..., "table_attached": false, "table_bytes": 0}`, so the data-only case is no longer reported as incomplete: fixed as not-even-correct rather than merely reworded. No harness assertion or note read either field, verified rather than assumed: run-mirror reads `.ok`, `.hooks.data` and `.hooks.control` and nothing else from the report.

### The mirror review round

Both reviewers took the harness before it landed, and the execution-focused pass proved the round's defect with a chain worth keeping: the two diff-report pipelines each sat as the last command of an if body, so under pipefail a differing mirror killed the script before the FAIL accumulator, the banner, or the golden comparison ran; and because the --update copy was unconditional, the only thing preventing the capture of a divergent golden was that accident (the reviewer applied the natural one-line banner fix and watched --update commit a Go-only transcript while reporting FAILED). Two closing-round notes worth keeping: the implementer's own earlier red-proof output had shown the missing FAILED banner and was read as a pass because the exit code was 1 for the wrong reason (the exit status was checked, the output was not; both are part of a proof); and the brief's suggested fixture row physical-projectile-damage-1 was corrected to level 7, because in base 2.0 the level-1 damage techs carry a plain count and it is the final level that is formula-priced and infinite, so the fixture now asserts a shape the engine actually has. What held under attack: determinism across cold, warm and wiped runs; every refusal path loud with its remedy on a doctored PATH; anti-vacuity greps surviving mutations that keep both transcripts equal; refuse-before-compare ordering making stale-transcript comparisons unreachable; shellcheck clean; the serialiser proven canonical and locale-independent (probed under four locales; lua52f does not expose os.setlocale at all); and pin-transparency re-verified at the packaged-binary level.

### A data guest cannot raise its own message: fkdata surface gap, graded AWKWARD. RESOLVED upstream and adopted

The library's refusals (a cycle with its full path, an overwrite, a research_trigger CostOf) must stop the load loudly, and the design says failures raise at the stage naming the path, per fkdata's rule. But that rule is about the HOST's errors: read from runtime/lua/fk_data.lua and fk_rt.lua, a guest has no raise primitive at all. A panic compiles to a wasm trap, the trap surfaces as the Lua error "fklua trap: unreachable" (a code, not a message), and TinyGo on wasm-unknown has no print channel (at that time the built module imported exactly the seven fkdata functions plus env.fk_log, nothing else; it now imports eight, fkdata.raise having joined them). The loudest available shape is therefore fkdata.Log the full sentence, then trap: the player sees a load failure naming the mod, and the author finds the actual reason one line above the trap in factorio-current.log. It works, but the engine's error box shows the generic trap string rather than the library's carefully-built diagnostic. A guest-facing raise import in the fkdata ABI (message in, Lua error out, sorted with the stage name the way the host's own errors are) would let a validation library surface its message where the player is looking. Recorded as the round's headline ecosystem finding.

RESOLVED and adopted. `fkdata.Raise(msg)` / `fkdata::raise(msg) -> !` landed upstream and every diagnostic exit in this library now routes through it: `Emit`'s error path is a single `Raise` call, and the Log-then-panic shape and the comment narrative explaining it are deleted. The host prefixes the stage in `fk_data.lua`'s `fail()`, so the ADOPTION FORCED A MESSAGE RESHAPE across the library: refusals changed from `fkrecipes: at the <stage> stage, <what>` to `fkrecipes: <what>`, because a stage in both strings reaches the player twice in one sentence. 90 message expectations per language moved with them, symmetric to the count. What the player now reads, captured end to end through a packaged mod under the stand-in and byte-identical in both languages:

    fklua: at the data stage, fkrecipes: two technologies share the name hardened-tips; the second would overwrite the first

against what the same refusal produced before, where the error box carried a code and the sentence survived only as a log line:

    fklua trap: unreachable

CONSEQUENCE FOR THE World SEAM, decided rather than deferred: the stage was threaded into the planner for message-building alone, so with the prefix gone `StageName`/`stage_name` fed nothing. It is REMOVED from the trait in both languages. Keeping it "for the emit dispatch" would have been false comfort: the dispatch reads `fkdata.Stage()` directly and never asked the World, so the method was pure cost on every consumer who implements a World for their own host tests. The stage now has exactly one source, which is the host that prints it. `validate`, `validateSettings`, `checkResolvedCraftTimes` and `checkCycles` lost their stage parameters with it.

### The crafting-time floor, measured

Probed on Factorio 2.0.77 (build 84539, mac-arm64, steam; the binary re-asked its version before the runs), with a plain Lua probe mod under FACTORIO_USERDIR=/tmp/fkrecipes-probe and --dump-data:

- energy_required = 0 refuses the load, exit 1: `Error while loading recipe prototype "fkr-probe-zero" (recipe): energy_required can't be <= 0.001.`
- energy_required = -1 refuses identically (same message, exit 1).
- energy_required = 0.0011 and 0.002 both load (exit 0) and survive to data-raw-dump.json unchanged.
- An omitted energy_required stays absent in the dump (the engine applies its 0.5 default at runtime).

So the engine's floor is exclusive at 0.001: a value must be strictly greater. The library encodes this as a named floor constant (refuse plan values at or below it, quoting the engine's reason) and gives a generated crafting-time setting minimum_value = 0.002 when the consumer does not supply a minimum, so the settings GUI cannot produce a value that kills the next load. A consumer-supplied minimum at or below the floor is refused at plan time, and a bound value that arrives at or below the floor anyway (a colliding mod can silently overwrite a same-type setting name) refuses naming the setting rather than letting the engine blame the consumer.

The instruction to never read a gate's exit code through a pipe is recorded here as adopted for operator commands. ## The in-game gate

scripts/run-ingame.sh runs the packaged examples under the real engine (re-asked its version first: 2.0.77 build 84539), under FACTORIO_USERDIR=/tmp/fkrecipes so a running game's lock cannot kill the gate, and pins one golden line per engine: both normalised dump hashes (the settings dump hashed too, because setting prototypes never reach the data dump and a one-hash golden is green for a silent fk_settings; FkLua's recorded lesson) plus the mod set. Go and Rust produce identical hashes in-game; the whole gate is 17 to 18 seconds including builds; a mod-set mismatch reports SKIPPED loudly and exits 0 per the FkLua convention (a CI flag to make SKIPPED nonzero is recorded as open).

The phase's findings. First, the expected stand-in-versus-world question resolved in the stand-in's favour: base 2.0.77 really carries physical-projectile-damage-7 with count_formula 2^(L-7)*1000 and max_level infinite, exactly as the mirror models it; the gate now asserts CostOf's copy against the source prototype in the same dump rather than a transcribed number, so it checks faithfulness, not expectation. The stand-in's two deliberate flavour differences (pack list and prerequisites) are recorded as such. Second, an assertion the implementer got wrong and the library got right: in-game there is no mod-settings.dat, so EnabledBy reads its declared default and the technology comes out enabled with no hidden key; the switched-off branch belongs to the mirror, whose stand-in flips the setting. The two gates therefore cover opposite sides of the hidden-not-absent decision, and neither could cover both alone; the script says so in a comment. The ladder-drop log line fires in real base too (no tungsten-carbide or titanium-plate there either), so fkdata.Log is exercised through the engine's own log.

The script review sustained five findings, fixed before the commit: a single-line local declaration evaluating a sibling assignment from the enclosing scope (working only because the caller's loop variable shared the name; the repo's first shellcheck warning); the hash pipeline wrapped in an echo command substitution, so a malformed dump would have produced the empty-input constant hash for both languages, satisfied the mirror and determinism checks, and could have reached a golden through --update (reworked to a normalised temp file with no pipes, the house lesson applied to its own gate); the userdir hardcoded while the docs described an env var (now an overridable default); run-mirror's tmp wipe taking run-ingame's subtree with it (both scripts now own disjoint subtrees); and two preconditions failing in bash's voice rather than the script's. What held: three-run determinism from a fully cold userdir, every cheap refusal loud with its remedy, the fully guarded --update flow, SKIPPED unable to mask a same-run FAIL, all ten jq assertions non-vacuous with real values on both sides, and a golden whose recorded mod set is byte-identical to what the engine's log actually said.

## Design deviations

Every deviation lands here with the evidence that forced it.

- docs-style.md is carried as a copy of FkLua's with one section adapted: the licence-statements paragraph named FkLua's third-party inputs (testdata/spec, third_party/lua-5.2.1), which do not exist here, so it now states FkRecipes' own MIT position. Everything else is verbatim.
- The em-dash and en-dash ban is extended to working notes and every error message (the parents exempt working notes). Recorded in CLAUDE.md's critical rules.
- **max_level is not a unit field.** The design says CostOf copies "the whole unit including count_formula/max_level verbatim", but the engine keeps max_level on the technology prototype, beside unit, not inside it. A verbatim unit copy therefore cannot carry it. Resolution: World grew TechMaxLevel (a Value, since the engine's field is a number or the string "infinite"), and CostOf copies it onto the generated technology separately; count_formula rides inside the unit copy as the design expected. The unit copy itself is proven a copy by an unrecognised key surviving byte for byte.
- **The sketch's functional options became spec structs and typed 1-based handles**, so the two languages mirror field for field (Go zero values and Rust Default both mean absent) and a reference to an undeclared or foreign thing is refused rather than representable. The dropdown constructor is named DropdownSettingNeedingLocale; the name is the design's required mark that dropdown values have no inline localisation.
- **Overwrite is refused, not performed.** A planned item, recipe or technology whose prefixed name already exists in data.raw is a refusal, not a silent data:extend overwrite. This also closes a cycle-validator blind spot found in review: a duplicate node in the overlay would bind incoming edges to the stale copy and accept a real cycle. Consequence, to document for consumers: Emit runs from exactly one data-stage hook.
- **TechSpec.AfterTech is a surface addition.** The design's InsertBetween/After anchor only external names, so a plan could not chain its own technologies (the anchor probe against data.raw logged a drop and detached the chain). AfterTech anchors on a plan-declared technology by handle. An AfterTech edge cannot close a cycle: the handle only exists after the technology it names, so the edges run backwards through declaration order, and Before with AfterTech is refused so nothing existing is rewritten to require the new node. The argument is recorded at the branch in both halves.
- **A pre-existing cycle in the world's own tree is refused with the full path** even when the plan adds no edge to it. The design only demands the overlay walk; refusing the inherited cycle is strictly more information than the engine's eight-word abort, which the load was heading for anyway.

## The adversarial review rounds

Maintainer rule, applied retroactively: all Rust must pass adversarial review before commit; after the Rust rounds kept finding real defects, the maintainer extended the pass to the Go half, informed by the Rust catalogue. The Go round found three blockers the Rust pass structurally could not see: the per-Lib id counter was a plain package var (proven racy: 4662 duplicate ids under 20000 concurrent New calls, reopening silent cross-plan handle resolution for consumers running parallel tests; fixed with sync/atomic and a -race gate), all seven handle types were mutually convertible because Go treats identically-shaped structs as identical types (fkrecipes.BoolSettingRef(anIntSettingRef) compiled in a consumer package and silently hid a technology; fixed with distinct zero-size marker fields), and the two languages' shortest-round-trip float formatters break representation ties differently, so host transcripts diverged on real float paths including the verbatim CostOf unit copy (6118 divergences per 1.15M matched samples, with a formatter-parity test that could not fail; fixed by replacing both test formatters with one deterministic 17-significant-digit rule). It also found: Lib copyable by value with two copies appending into one backing array (fixed with a noCopy vet guard), specs aliasing caller slices so one unchanged Lib could give two different plans (fixed by copying on declaration), missing sign guards on every amount but the unit count plus a negative CraftTime silently swallowed (fixed with refusals), silent rounding of int64 amounts above 2^53 (fixed with a refusal at the exact boundary), a unit-shape guard on CostOf, Go returning live slices where Rust clones, and a nil-World panic (Go-only guard; a Rust &dyn World cannot be null). The TinyGo build tag, the message parity (every refusal string byte-identical across the halves), the full re-run of the Rust attack catalogue against Go, and the pure planner's TinyGo compile (12340 flash bytes, no reflect, no fmt, no sort) all held. After the guard round the library measures 13914 flash bytes (+12.8 percent, the guards and their message strings; sync/atomic cost 23 bytes, the handle markers cost zero).

One symmetry to leave alone: Go carries a nil-World guard that Rust cannot reach (&dyn World is never null), while Rust carries a zero-id Lib check that safe Rust cannot reach (Default is gone; kept for mirror symmetry with Go, whose zero value cannot be suppressed). These are opposite policies about unreachable guards, each right for its language; do not tidy either away.

Honest caveats from the closing round, recorded rather than smoothed: the noCopy guard on Lib converts a silent corruption into a vet finding, and copylocks is not in go test's default vet subset, so a consumer who never runs go vet can still copy a Lib and corrupt both copies' plans; that is the standard Go idiom's ceiling, stated so "fixed" is not read as "unrepresentable". A typed-nil World still panics (no interface nil check can see it; Go-inherent, no Rust equivalent). The defensive clones (Go cloning where Rust clones) carry no red proof, because the aliased lists are read-only downstream and removing the clones changes no output; that is mirror parity, not a fixed bug. The refusal-ordering fix's originally-briefed test shape was unreachable (two invalid no-name recipes refuse on the first result check before any duplicate scan) and the vacuous first test was replaced with the reachable shape. Two thresholds sit deliberately one apart: validation accepts amounts up to and including 2^53 while the transcript formatter's plain-digit path stops strictly below it, so the boundary value renders in scientific form, identically in both halves. Left open for the next phase: a declaration with a literally empty name is not refused yet. The first review (whole rust/ tree, differential-fuzzed against the Go mirror with matched LCG generators, 8000 cases, zero divergence) confirmed the core and found: two blockers (EnabledBy indexed without validation, a reachable panic from a foreign handle; the example placeholder not compiling for wasm because nothing linked the panic handler), three defects (the cycle blind spot above; in-range handles from another Lib silently resolving to the wrong declaration; no intra-plan chaining), and hardening items (per-Lib handle tags, non-finite float refusals including UnitSpec.Seconds, empty mod name refusals, a 100-node cap on the cycle path message, Go int widths moved to int64 because TinyGo's wasm int is 32 bits, fixture units re-sorted to the order fkdata actually hands back, resolver/profile/autoexamples added to rust/Cargo.toml, the host-gate comment corrected: cargo resolves and clones the git graph even for a host test run, so that gate needs the network once). One review item accepted as-is: the Op stream's payloads are public and therefore forgeable; the op stream is the emit layer's internal seam and a consumer forging ops is out of contract. One requested red proof was correctly refused by the implementer: a cycle through AfterTech edges is unreachable by construction (argument above).

One proof vacuity was found and fixed during the round: the guard keeping max_level off hand-rolled units could not go red because the fixture answered "no cap" for the empty name; the fixture now answers for any name, making the guard observable. Lesson recorded: a red proof that stays green indicts the test first.

## The locale checker

BetterBeltBalancer's tripwire standardised: pure, host-testable, both directions, in both languages, pinned to one committed golden over one committed fixture cfg (the design's cheapest cross-language pin, working with no toolchain installed). Parsing semantics are BBB's, which are the engine's, with the subtle one carried deliberately: the key is NOT trimmed around the equals sign, because Factorio takes everything before the first equals as the key, so a checker that tidied whitespace would pass a file the game reads differently. Two checks beyond the brief because BBB's parser reports them (an unparseable line, a key defined twice in one section), emitted first because a file the parser could not read makes every later finding suspect. One stated limitation rather than a silent gap: the [mod-setting-name] orphan rule can only police by mod prefix, so a setting the consumer wrote by hand in the same file reports as an orphan; the doc comment says so, and an opt-out is left for a consumer to ask for. The golden's four findings were predicted by hand before the implementation produced them, byte-identical from both halves.

The review round split usefully: the reference-diffing pass caught the one semantic defect (duplicate-key presence answered from any non-blank entry while the finding text promised last-wins, a false negative on exactly the shape a blank sneaks in through; BBB's overwrite semantics catch it), while the hostile-input pass proved what held (the cross-language Unicode whitespace tables identical across 13 probed codepoints, no UTF-8 slicing hazard, case-sensitive keys correctly not colliding) and measured the O(n squared) duplicate scan to 2.9 seconds at 50000 distinct keys. Fixed together: last-entry-wins presence; a missing-entry finding that names the section the key actually sits under (the precise form of the mis-cased-section hint; a blanket unknown-section finding would false-positive on every legitimate [item-name] section); a leading BOM reported once and stripped for the rest of the parse, with the comment stating the engine's BOM behaviour is unmeasured so the checker must not silently bless one; empty section headers and empty keys reported per the parser's own stated rule; a sorted-index duplicate scan and a 100-finding cap (the cycle-path precedent); quoting for keys that differ from their trimmed form. One deliberate divergence from the reference confirmed and documented: descriptions stay optional, because the engine's failure mode for a missing description is a lost tooltip, not an Unknown key render.

## The migration path (maintainer scope addition, 2026-08-31)

Mods with hand-rolled user settings must be able to switch to FkRecipes without losing player preferences, with BetterBeltBalancer as the pilot. The engine fact that shapes everything: Factorio persists startup values in mod-settings.dat by setting NAME, with no rename mechanism, so preferences survive exactly when the emitted names do not change. BBB's recon made the crux concrete: its packaged name is better-belt-balancer but all three settings carry the historical bbb- prefix, so none migrates by name-matching and every one needs an explicit legacy-name escape hatch; renames are proven harmful there (startup values silently reset, and the runtime-global bool is written per save by the mod's own grandfather pass). The recon also showed BBB's two cost settings drive exactly what the design charter promised settings could drive (an option-selected ingredient plan per dropdown value; a setting-chosen cost source whose prerequisite follows the copied unit), so the migration path adds those two charter verbs beside the Legacy constructors. Out of scope and documented as such: BBB's runtime-global engine-gated bool is a control-stage concern that stays hand-rolled beside lib.Emit in the mod's own fk_settings hook (the hook belongs to the mod; composition, not migration). The migration's acceptance criterion is BBB's own mod_settings_sha256 golden: a migrated settings stage must hash identically, which pins names, types, defaults, orders and allowed_values byte for byte. The end-to-end legacy exercise belongs to the BBB pilot in its own repository with its own goldens; this repository covers the Legacy constructors with unit and locale tests, and the two charter verbs ride the mirror and engine gates through the example.

The implementation round's own findings: the new tests caught two real bugs immediately (the enablement and crafting-time resolution paths built setting names as prefix plus name directly instead of through the single emittedName seam, so a legacy setting was looked up under a name it never had; both languages, both fixed); two pre-existing mirror anti-vacuity assertions were themselves vacuous (the max_level and count_formula greps were satisfied by the stand-in's own source row whether or not anything was copied) and are now anchored to the generated prototype, with the cap-and-formula coverage sitting on the engine gate where the copy is compared against the source in the same dump; and one check was kept without a red proof and said so (the ladder's exists condition is not independently observable, because a technology that does not exist also carries no unit, and a vacuous green test claiming coverage would be worse than the honest gap). The two ladders split across the gates deliberately: the mirror's stand-in flips the new dropdown and walks the military row, the engine gate runs on defaults and walks past a rung no vanilla install has to copy physical-projectile-damage-7 verbatim; neither gate could cover both. Both goldens were regenerated through their own --update flows, stated rather than slipped in.
